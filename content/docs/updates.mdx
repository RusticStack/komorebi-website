## Check for updates

Settings > About > **Check for updates** asks GitHub for the latest release. With **Check for updates automatically** on, Komorebi checks at most once a day.

A check is one HTTPS request to `api.github.com`, with the User-Agent `Komorebi/<version>`. Nothing about you or your mail.

## Install an update

<Steps>
<Step title="Press Download and install">

Nothing downloads before that.

</Step>
<Step title="Komorebi checks the files">

It downloads the installer, its `.sha256` and its `.sig` into a temporary folder.

</Step>
<Step title="The update runs">

Only if both checks pass. It closes Komorebi, updates it and starts it again.

</Step>
</Steps>

## The two checks

1. The installer's SHA-256 matches the published `.sha256`.
2. The Ed25519 signature verifies against the key built into Komorebi. It covers the version and the hash, so an older installer cannot pass as a newer one.

<Callout title="Not the same as Authenticode">
This signature protects in-app updates. SmartScreen looks for Authenticode, which releases do not have yet. See the [code signing policy](/code-signing).
</Callout>

<Advanced title="Verify a release yourself">

Compare the installer's SHA-256 with the `.sha256` file, as in [Install Komorebi](/docs/getting-started#check-the-download). With the source code, the `sign_update` example checks the signature:

```powershell
cargo run --example sign_update -- verify komorebi-0.7.0-setup.exe 0.7.0
```

The private signing key stays with the maintainer, outside the repository.

</Advanced>
